# Browser-local market simulation

> **Retired simulator documentation.** The active main experience is now the
> [Get-Funded exchange](get-funded-simulation.md). The old engine, configuration
> controls, checkpoint format, and structural bot cohorts described below are
> preserved for reference/tests and are not imported by the active trading page.
> Existing chart improvements remain in use with the new authoritative exchange.

The Simulation page runs BX, BT and BG in that order on a shared Park–Miller random stream. The reproducible seed is 73521. Initialization creates five makers, 36 weighted ordinary traders and three whales per instrument, posts the opening quotes, and crosses them in an opening auction. It then adds two supply & demand traders and two support & resistance traders per instrument, bringing the default population to 48 per instrument (144 total), before running 7,200 quarter-second steps. Chart history is generated entirely by exchange executions.

`simulationModel.ts` defines contract economics, configuration, state, RNG and candle aggregation. `simulationExchange.ts` implements price/time matching and signed futures accounting. `simulationParticipants.ts` ports the bot scheduler, regimes and news from the reference Luau source. `simulationPreview.ts` exposes immutable advancement and selected-instrument read models. The UI never draws from the RNG.

## Structural participants

`simulationStructure.ts` implements four approaches using only completed 1-minute execution candles. Each participant has its own deterministic random stream, seeded from the run seed and participant ID, with different lookback, volatility period, patience, tolerances, pivot windows and decision schedule. These strategies never read hidden fair value, regimes or news. Chart selections cannot affect their inputs. Structural analysis runs at minute boundaries before queued exits or liquidations match orders, so an invalidated entry is cancelled before further matching. Empty minutes age structures without fabricating candles.

Supply & demand traders detect a compact 2–4 candle base followed by a strong departure, using prior completed candles' average true range. A zone records the base's high and low and becomes available only when the departure closes. One trader posts a patient limit as price approaches a fresh zone; the other requires a returning candle to reject the zone and close beyond its near edge in the intended direction. A decisive close through the far edge, age, or more than the seeded 2–3 separated tests retires the zone. Fresh zones receive priority; each patient entry is attempted only once per zone.

Support & resistance traders confirm strict swing pivots after the seeded 2–3 later candles have closed, merge nearby same-side levels with a volatility-adjusted tolerance, and require at least two separated tests before trading. One trades closed-candle support bounces and resistance rejections. The other waits for a close beyond a mature level, then a successful retest on a later candle. A close through a level invalidates it; breakout candidates survive separately until a retest, failure or expiry. Levels expire after their last relevant test becomes stale. Consumed signal identities prevent repeated entries from the same excursion.

Orders are 1–2 contracts and each account has a two-contract inventory limit. Existing exchange capital, margin, expiry and liquidation rules apply. A working entry or open position prevents a second entry; a partially filled entry's remaining quantity is cancelled at the next strategy decision (or earlier if the setup invalidates or its protection triggers). Stops remain beyond the structure with a volatility/tick buffer, including across partial fills and price improvement. Targets use the nearest eligible opposing structure, one tick before its near edge, or the configured reward/risk fallback. Entries lacking minimum target room wait. Confirmed entries use a marketable limit capped at two ticks of adverse slippage and at the minimum reward/risk price, then cancel any remainder. The exchange checks absolute bracket room at every actual fill. Stops and targets trigger reduce-only market orders through the existing book; exits may slip or remain pending without liquidity.

`SimulationConfig.supplyDemandTraders` and `supportResistanceTraders` each default to 2 and accept 0–2. Set both to 0 when calling `createSimulation` to retain the original 44-participant reference behavior, including the exact shared RNG draw order and unchanged Luau fixtures. `structureRewardRisk` defaults to 2 and `structureMinRewardRisk` to 1.25; checkpoint validation accepts 1–10 with the minimum no greater than the fallback. These are engine configuration fields, separate from the existing environment override controls.

Each structural participant retains at most 64 completed bars, 12 zones, 20 levels and 64 consumed signals. The minute cursor, private RNG, parameters, structures, test counters, pending breakout, setup, entry order identity and decision explanation are all checkpointed. Existing version 2 runs without the structural configuration migrate once by appending accounts with stable IDs. The migration preserves time, prices, positions, orders, existing participant schedules, shared RNG and history. It seeds only the new traders' bounded candle caches; it does not replay old signals. Explicit zero counts remain zero. Compatible hot replacement performs the same migration on a cloned live snapshot.

Both cohorts appear in group summaries, order-book contributions and individual filters. Individual inspection shows the approach, watched zone or level, current setup, decision reason and completed-minute coverage alongside the existing account ledger. Chart layout and the latest-eight/latest-two activity feeds are unchanged.

Each execution updates all five timeframes independently. Opens are the first execution in the bucket; empty windows do not create candles. Quantity is counted once, even though both bot accounts settle. Market remainders cancel, limit remainders rest, and crossing an older self quote cancels that quote without printing volume. Stops, targets and forced bot liquidation submit into the same book. There is no player order interface or broker integration.

The default clock targets 18 simulated seconds per real second, multiplied by the speed selector. A delivered batch advances at most 32 steps; hidden/offline time is discarded. Navigation and compatible hot replacement share the same runtime. Published snapshots remain immutable. Playback publishes each delivered 50 ms clock batch (20 updates per second), avoiding dropped publications around a timer cutoff. Boundary advancement publishes at most every 50 ms; navigation and user controls respond immediately. Switching instruments or timeframes only changes the view.

## Workspace and chart controls

Wheel up zooms in and wheel down zooms out at the candle under the pointer. A native non-passive listener normalizes pixel, line and page deltas and consumes scrolling only over the SVG. Touch supports one-finger pan and two-finger pinch. Candle spacing is bounded to 0.5–80 CSS pixels. Sparse series contain only execution-bearing buckets; horizontal distance counts actual candles, while labels and measurements report their actual simulated times.

Drag the plot to pan time and price. Drag the right price axis vertically to scale price; drag the bottom time axis horizontally to scale time. **Follow Latest** / **Home** resumes time following without changing zoom or the price mode. **Auto Price Scale** independently fits the visible candle range. **Fit History** fits all retained candles and enables auto price; **Reset View** / **R** / double-click restores 12-pixel spacing, following and auto price for the current view. **+ / −** zoom, **Shift + / −** scale price, **Page Up / Down** pan time, **↑ / ↓** pan price and **← / →** inspect candles. **A** toggles auto price, **M** toggles measurement, **Enter** places a measurement endpoint at the inspected close and **Escape** clears inspection. **Chart tools → Shortcuts** explains these controls.

Historical viewports store a candle timestamp plus a fractional slot offset. Appends and eviction before that timestamp preserve its horizontal position; an evicted anchor clamps to the earliest remaining data. Resizing keeps the historical left anchor. Each instrument/timeframe has its own view preference; indicators and panel preferences are shared. Resetting the run resets all 15 chart viewports while retaining indicator and layout settings. Earliest retained time is labeled, and an arrow on the last-price tag indicates a price outside the visible range.

The chart displays price only, using the full plotting height above the time axis. The volume histogram and its hover readout are removed. Execution quantities remain available to the engine, tape and optional VWAP overlay.

**Measure** selects two tick-snapped price/time points and shows price change, percentage, ticks, inclusive candle count and actual simulated seconds. An evicted endpoint is reported as unavailable. Jump accepts retained simulated seconds; an empty bucket selects the nearest available candle without fabricating data or moving engine time. Event selection shows the event beside the chart and inspects its candle. There is no cursor-based engine rewind.

The desktop workspace fits the available viewport below the app header. A compact toolbar keeps Pause/Resume, Reset, speed, instrument and timeframe visible above the chart. Last price, spread and volume share the heading; playback, elapsed time, news and local-save status share the bottom strip. The chart fills the remaining height, including when a previously saved minimum chart height would exceed the viewport. **Chart tools** opens an anchored panel for fit/reset, measurement, indicators, jump and shortcuts without moving the plot.

The collapsible side panel opens to **Participants**, with maker liquidity and whale frequency controls above expandable group ledgers and individual inspection. **Book**, **Activity** and **Stats** switch the same panel to depth, tape/events and detailed metrics. Long panel contents scroll independently, keeping the chart and playback controls visible. **Advanced settings** is a modal drawer, closed by default, containing seed, step/boundary advancement, full environment overrides, display preferences, checkpoint import/export and market explanations. Escape closes the drawer and restores focus. The bounded chart-height preference (300–720 px) applies on small screens; book width (260–460 px) applies where space permits. Below 800 px the side panel stacks below the chart.

**Expand workspace** opens the same controls and panels in a viewport-sized portal; Exit or Escape returns to the app. Escape closes an open settings drawer or chart-tools panel before leaving the expanded workspace.

## Playback and inspection

Pause enables **Step 0.25s**, which executes one engine step, and **Next timeframe boundary**, which executes real steps to the next strict boundary. Boundary work runs in batches of at most 32, yielding between batches; Cancel leaves the exact completed state paused. Hidden tabs suspend advancement, and no hidden-time catch-up is queued. Daily advancement can take time; its remaining step count is visible. Reset requires an explicit replacement confirmation and offers export first. Seeds must be integers in −2147483646…2147483646.

The book identifies best bid/ask, last execution, spread, level quantity and cumulative depth (Σ). Wheel and keyboard navigation hold the chosen price center. Follow Price recenters only near an edge after a dwell; Recenter restores it immediately. Selecting a quantity exposes current group contributions at that price. Missing sides remain visibly unavailable.

All price-ladder rows reserve 28 pixels, including empty levels, with fixed line heights for quantity and cumulative depth. Live orders therefore cannot change the book height, shift the chart footer, or move the page through scroll anchoring. Browser measurements confirmed identical chart and panel bounds across eight changing order-book states during playback.

The selected-instrument tape displays actual execution times (including quarter seconds), prices, quantities and aggressor side. It continuously shows the latest eight matching executions, with optional aggressor filtering. The event timeline shows the latest two shared news, regime or manual override events. Both panels put the newest entry first, with no internal scrolling, pagination or frozen inspection. The engine still retains up to 4,000 executions and 40 events. Override metadata is appended without RNG draws; reference market decisions and draw order remain unchanged.

SMA uses actual candle closes and is unavailable before its full lookback. VWAP uses exact execution quantity and price from the retained tape only; its coverage start is shown and it is never called session VWAP. Both remain analysis overlays, visually distinct from price candles. Individual participants can be searched by ID and filtered by group/status. Inventory, realized/unrealized P&L, equity, position margin, worst resting exposure, engine risk allowance, protective exits and halted/liquidating state come from the same published snapshot as the chart/book/metrics.

Overrides are drafts until Apply. Each field shows its range and applied value, with its explanation in a label tooltip; Default values restores the visible fields to 1×. Participant controls apply only their visible fields, leaving unapplied advanced drafts intact. Applying changes affects future decisions and scheduling, preserving existing positions and history. Reset uses the applied settings.

## Persistence

The version 2 checkpoint at `topsignal.simulation.session.v2.owned` stores the complete continuation state, selected view and fractional step. On first use it reads the prior `topsignal.simulation.session.v2` checkpoint without modifying that source. Once the protected save exists, old clients writing the previous key cannot roll it back or pause playback. An unreadable protected save never falls back to an older run. The checkpoint file format remains version 2. Candle/tape arrays use lossless compact tuples on disk. Each of the 15 candle series retains at most 1,200 bars, the tape retains 4,000 executions, recent prices retain 64 executions per instrument, and event history retains 40 events. Each serialized save is capped at 4.5 MB using conservative UTF-16 byte accounting; quota failures leave the prior save intact and show an in-memory-only status.

The legacy `topsignal.simulation.session.v1` value is neither migrated nor overwritten. A notice identifies preserved legacy data. An unreadable version 2 save is protected from automatic writes until explicit Reset or confirmed import. No simulation arrays or state are sent to Supabase.

Export downloads a versioned JSON checkpoint with the exact RNG, accounts, schedules, resting orders, pending exits, retained arrays and fractional progress. Import checks size before parsing, schema/version, finite numeric bounds, tuple shapes, price/time ordering, ledgers, volume/close consistency and order ownership. It writes the replacement to local storage before changing the active run. Invalid files and storage failures preserve the current run and prior save. Successful imports pause; Resume continues the imported engine exactly. Import changes the selected instrument/timeframe but keeps this browser's separate workspace preferences at `topsignal.simulation.workspace.v1.*`.

Web Locks provides one writer per origin in supported secure-context browsers. A short-lived owner token at `topsignal.simulation.writer.v1` also fences former writers before advancement or saving, including browsers without Web Locks. A second tab is paused with a conflict banner beside Resume and cannot reset/import/advance. Storage revision checks detect external replacement before saving. Export any desired in-memory state, then choose **Use this tab** to revoke the prior lock and load the latest saved run paused. Updated clients stop on revocation; obsolete clients cannot modify the protected checkpoint. **Load saved run / retry ownership** acquires only an available owner slot. Navigation within a tab retains ownership and the singleton runtime. Compatible HMR waits for asynchronous lock release before reacquiring ownership, preserves live memory, and forwards mounted controls to the replacement controller. Status reports the last saved simulated time; failed saves remain visibly memory-only.

Snapshots clone all mutable decision state, while copying the bounded array containers for immutable existing candles/executions. Candle aggregation replaces active objects, so prior published snapshots remain unchanged. This avoids cloning up to 18,000 completed candle objects per playback batch. Memoized candle glyphs avoid reconciling unchanged shapes during live updates. Below three-pixel spacing, equivalent candle and wick rectangles are batched into a few SVG paths by direction. The visible slice and rendered candle elements are cached so cursor movement does not rebuild them. Disabled SMA does no indicator calculation. These optimizations neither skip engine steps nor change random draw order.

In development, React 19 records changed component props in User Timing measures. Large candle/tape/market props incurred repeated serialization costs even after their timing entries were cleared. The chart, activity feed and individual participants now subscribe directly to the same runtime snapshot, keeping full histories out of changing component props. Dense candle path construction also runs inside the chart rather than passing the history through another component. The runtime still clears prior simulation component measures, including retired component names from hot updates; unrelated timing entries remain intact.
